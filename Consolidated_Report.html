Case Study 20: University Admission Decision Engine

1. Problem Statement

Design and implement an automated decision-support system for a competitive engineering university admissions board. The engine evaluates applicants based on their academic scores in Mathematics, Physics, and Chemistry (PCM), entrance examination rank, affirmative action category (GEN, OBC, SC, ST), and personal interview score. The system must verify subject and aggregate cutoff criteria with category-specific relaxations, compute a weighted Composite Merit Index (CMI), resolve rank ties using an ordered multi-criteria tie-breaking algorithm, and allocate available seats across Open Merit and Category Reserved quotas. ---

2. Objectives

- Accurately parse heterogeneous applicant records stored as tuples. - Evaluate multi-tier conditional cutoff rules (both general and relaxed category rules). - Calculate a normalized Composite Merit Index (CMI) combining board marks, entrance rank, and interview performance. - Implement an in-place multi-criteria tie-breaking sorting algorithm without using external libraries, custom functions, or built-in lambda key functions. - Allocate seats fairly following Open Merit and Category Quota rules. - Strictly adhere to allowed core syllabus concepts: variables, operators, conditionals, loops, lists, and tuple unpacking. ---

3. Assumptions

- Applicant tuples follow the fixed format: (applicant_id, name, math, physics, chemistry, entrance_rank, category, interview). - Board marks are between 0 and 100. Interview scores are between 0 and 25. Entrance ranks are integers from 1 to 10,000 (lower rank number indicates superior performance). - General Category cutoffs: PCM Total $\ge 180$, Math $\ge 60$, Physics $\ge 55$, Chemistry $\ge 50$. - Reserved Categories (OBC, SC, ST) receive a 10% relaxation on cutoffs: PCM Total $\ge 162$, Math $\ge 54$, Physics $\ge 49$, Chemistry $\ge 45$. - Tie-breaking hierarchy: 1. Primary: Composite Merit Index (CMI) (descending). 2. Tie-break 1: Mathematics score (descending). 3. Tie-break 2: Physics score (descending). 4. Tie-break 3: Interview score (descending). 5. Tie-break 4: Entrance exam rank (ascending, i.e., lower numeric rank is better). ---

4. Algorithm

- Step 1: Initialize applicant records as a list of tuples. - Step 2: Define seat quotas: TOTAL_SEATS = 3, CATEGORY_RESERVED_SEATS = 1, OPEN_SEATS = 2. - Step 3: For each applicant record in the list: - Unpack (applicant_id, name, math, physics, chemistry, rank, category, interview). - Check category-based eligibility criteria. - If eligible: - Compute $PCM\_Percentage = (math + physics + chemistry) / 3.0$. - Compute $Normalized\_Rank = (10000 - rank) / 100.0$. - Compute $Normalized\_Interview = (interview / 25.0) \times 100.0$. - Compute $CMI = (PCM\_Percentage \times 0.50) + (Normalized\_Rank \times 0.30) + (Normalized\_Interview \times 0.20)$. - Append evaluated tuple to eligible_applicants. - Else: - Append rejection reason to ineligible_applicants. - Step 4: Sort eligible_applicants using nested loop comparison (Bubble Sort): - Compare adjacent candidates by CMI. - If CMI is equal, compare Math scores; if tied, compare Physics scores; if tied, compare Interview scores; if tied, compare Entrance Ranks. - Swap adjacent candidates if the successor has higher merit. - Step 5: Traverse sorted merit list and allocate: - If open seats remain, allocate ADMITTED (Open Merit). - Else if candidate belongs to reserved category and reserved seats remain, allocate ADMITTED (Category Quota). - Otherwise, mark as WAITLISTED. - Step 6: Display final tabular admission decision sheet and summary statistics. ---

    SET OPEN_SEATS = TOTAL_SEATS - CATEGORY_SEATS

        pcm = m + p + c
        IF cat == "GEN" THEN
            min_pcm = 180, min_m = 60, min_p = 55, min_c = 50
        ELSE
            min_pcm = 162, min_m = 54, min_p = 49, min_c = 45
        END IF

        IF pcm >= min_pcm AND m >= min_m AND p >= min_p AND c >= min_c THEN
            pcm_pct = pcm / 3.0
            norm_rank = (10000 - rk) / 100.0
            norm_intv = (intv / 25.0) * 100.0
            cmi = ROUND((pcm_pct * 0.50) + (norm_rank * 0.30) + (norm_intv * 0.20), 2)
            APPEND (cmi, m, p, intv, 10000 - rk, id, name, cat, pcm, rk) TO eligible_list
        ELSE
            APPEND (id, name, cat, reason) TO ineligible_list
        END IF
    END FOR

    // In-place Bubble Sort for multi-criteria tie-breaking
    FOR i FROM 0 TO LENGTH(eligible_list) - 2:
        FOR j FROM 0 TO LENGTH(eligible_list) - i - 2:
            IF eligible_list[j] should yield to eligible_list[j+1] on (CMI, Math, Physics, Intv, Rank) THEN
                SWAP eligible_list[j], eligible_list[j+1]
            END IF
        END FOR
    END FOR

    FOR EACH candidate IN eligible_list:
        IF open_count < OPEN_SEATS THEN
            status = "ADMITTED (Open Merit)"

            status = "ADMITTED (Category Quota: " + candidate.cat + ")"
            cat_count = cat_count + 1

            status = "WAITLISTED"

    END FOR

Case Study 26: Nested Loop Examination Seating Generator

1. Problem Statement

Educational institutions require robust anti-malpractice seating arrangements for mid-semester and end-semester examinations. When students from two differing departments (e.g., Computer Science and Electronics Engineering) share an examination hall of dimension $R \times C$, no two students from the same department may be seated adjacent to one another horizontally or vertically. Additionally, damaged or reserved desks must be accounted for without disrupting the alternating pattern. The system must validate capacity, generate a 2D seating matrix using nested loops, and run an automated adjacency audit to guarantee compliance. ---

2. Objectives

- Model an $R \times C$ examination hall as a dynamic 2D nested list (matrix). - Validate total student counts against total and usable desk capacity. - Implement nested loop matrix traversal adhering to a parity-based alternation rule: $(r + c) \pmod 2$. - Gracefully bypass blocked/reserved desks while handling uneven class sizes with [EMPTY] indicators. - Execute an adjacency audit checking all cardinal neighbors (horizontal and vertical) to verify zero same-department adjacency. - Adhere strictly to allowed syllabus constructs: variables, nested loops, conditional statements, nested lists, and string slicing. ---

3. Assumptions

- Hall dimensions $R$ (rows) and $C$ (columns) are positive integers. - Two student cohorts are provided as lists of roll number strings (e.g., CS101, EC201), where the first two letters denote the department identifier. - Alternation rule: Cells where $(row + col) \equiv 0 \pmod 2$ are allocated to Department A; cells where $(row + col) \equiv 1 \pmod 2$ are allocated to Department B. - Blocked desks are represented as a list of coordinate tuples: (row_index, col_index). - If candidates in a cohort are exhausted before available alternating slots, remaining slots are labeled [EMPTY]. ---

4. Algorithm

- Step 1: Read hall dimensions ($R$, $C$), student cohorts for Department A and Department B, and list of blocked coordinates. - Step 2: Compute $Total\_Capacity = R \times C$ and $Usable\_Capacity = Total\_Capacity - len(blocked\_seats)$. - Step 3: Validate whether $(len(students\_a) + len(students\_b)) \le Usable\_Capacity$. If false, display capacity error. - Step 4: Initialize an empty 2D matrix of dimensions $R \times C$ populated with placeholder strings. - Step 5: Traverse blocked_seats and update matrix cells at coordinates $(r, c)$ to [BLOCKED]. - Step 6: Initialize index pointers $idx\_a = 0$ and $idx\_b = 0$. - Step 7: Using nested loops for row $r \in [0, R-1]$ and column $c \in [0, C-1]$: - If cell $(r, c)$ is [BLOCKED], skip to the next iteration. - If $(r + c) \pmod 2 == 0$: - If $idx\_a < len(students\_a)$, place $students\_a[idx\_a]$ and increment $idx\_a$. - Else, assign [EMPTY]. - Else: - If $idx\_b < len(students\_b)$, place $students\_b[idx\_b]$ and increment $idx\_b$. - Else, assign [EMPTY]. - Step 8: Traverse the generated matrix with nested loops to audit adjacency: - For each non-empty, non-blocked cell $(r, c)$, compare department prefix with right neighbor $(r, c+1)$ and down neighbor $(r+1, c)$. - Record any violation where adjacent department prefixes match. - Step 9: Render formatted 2D seating grid with row/column headers and report summary seating density metrics. ---

Case Study 35: Text Compression Using Character Runs (Run-Length Encoding)

1. Problem Statement

Repetitive textual data and simple raster graphics frequently contain long consecutive sequences of identical characters. Run-Length Encoding (RLE) is a foundational lossless data compression technique that replaces repeating consecutive characters (runs) with a single character value and a counter. The objective is to design, implement, and benchmark an RLE text compression and decompression engine that accurately compresses textual data, verifies lossless reconstruction through inverse parsing, computes comprehensive statistical efficiency metrics, and identifies edge-case payload inflation. ---

2. Objectives

- Implement single-pass sequential string traversal using character accumulators to compress repeating characters. - Design an inverse decompression algorithm capable of parsing multi-digit run numbers and reconstructing the original payload without external libraries. - Formally verify data integrity through automated assertion ($Decompressed == Original$). - Calculate quantitative compression performance metrics: original length, compressed length, compression ratio, space savings percentage, and run distribution statistics (min, max, and average run lengths). - Evaluate negative compression (data inflation) on non-repetitive worst-case inputs. - Adhere strictly to allowed syllabus constructs: variables, loops, conditional statements, lists, tuples, and string operations. ---

3. Assumptions

- Input text consists of alphanumeric characters without whitespace or negative signs. - Compression output format: concatenated [Count][Character] tokens (e.g., AAAA $\rightarrow$ 4A). - Multi-digit runs are fully supported (e.g., 36M represents 36 consecutive 'M' characters). - Memory complexity must remain linear $\mathcal{O}(N)$ without employing forbidden libraries (re, itertools, or third-party compressors). ---

4. Algorithm

### Compression (Encoding) - Step 1: Read the source string raw_text of length $N$. - Step 2: If $N == 0$, exit with an empty result. - Step 3: Initialize current_char = raw_text[0], run_count = 1, and compressed_str = "". - Step 4: Iterate index idx from $1$ to $N - 1$: - If raw_text[idx] == current_char, increment run_count by 1. - Else: - Append str(run_count) + current_char to compressed_str. - Record (current_char, run_count) in run_records. - Set current_char = raw_text[idx] and reset run_count = 1. - Step 5: Append the final run (str(run_count) + current_char) to compressed_str. ### Decompression (Decoding) - Step 6: Initialize decompressed_str = "" and digit_buffer = "". - Step 7: For each character ch in compressed_str: - If '0' <= ch <= '9', append ch to digit_buffer. - Else: - Convert digit_buffer to integer repeat_count. - Append (ch * repeat_count) to decompressed_str. - Reset digit_buffer = "". - Step 8: Validate whether decompressed_str == raw_text. ### Metric Computation - Step 9: Compute: - $Compression\_Ratio = (Compressed\_Length / Original\_Length) \times 100\%$ - $Space\_Savings = ((Original\_Length - Compressed\_Length) / Original\_Length) \times 100\%$ - Traverse run_records to determine min_run, max_run, and avg_run. - Step 10: Classify viability: Beneficial, Neutral, or Inflationary. ---

1. Problem Statement

Before administering examinations, university exam controllers must rigorously audit proposed room seating plans. Unlike generator systems that build plans from scratch, an integrity validator must inspect an existing $R \times C$ seating plan to identify human error, administrative slip-ups, and anti-cheating infringements. Specifically, the validator must detect: (1) duplicate seat assignments for the same roll number, (2) unauthorized student allocations to physically damaged or reserved desks, (3) empty desk tracking, and (4) branch adjacency violations where students from the same department sit directly next to each other horizontally or vertically. ---

2. Objectives

- Traverse and inspect a 2D nested list representation of an examination hall grid. - Implement duplicate detection across all allocated cells without using forbidden set data structures or dictionaries. - Validate cell coordinates against an official designated list of reserved/damaged desk coordinate tuples. - Perform orthogonal neighbor checking (horizontal and vertical adjacency) to audit adherence to inter-branch separation. - Generate an audit discrepancy log specifying exact coordinates and issue descriptions, followed by a binary compliance verdict (PASSED / FAILED). - Strictly adhere to 1st-year B.Tech syllabus guidelines: variables, conditionals, loops, nested lists, parallel tracking lists, and tuples. ---

3. Assumptions

- The hall seating plan is stored as a 2D nested list of dimensions $R \times C$. - Desks may contain: - Valid student roll number strings (e.g., CS101, EC202). - Empty desk placeholders: [EMPTY], EMPTY, or ---. - Legitimate reserved seat placeholders: [RESERVED], RESERVED, or [BLOCKED]. - The first two letters of any active roll number identify the student's academic branch (e.g., CS, EC). - Reserved/damaged desks are defined by coordinate tuples (row_index, col_index). ---

4. Algorithm

- Step 1: Read the examination hall dimensions $R$ and $C$, the official reserved_coords list of tuples, and the $R \times C$ 2D seating matrix hall_grid. - Step 2: Initialize tracking structures: - seen_students = [], seen_positions = [] for linear duplicate tracking. - duplicate_errors = [], reserved_violations = [], adjacency_violations = []. - Counters: occupied_count = 0, empty_count = 0. - Step 3 (Single-Cell Inspection Loop): Iterate through each row $r \in [0, R-1]$ and column $c \in [0, C-1]$: - If cell is empty ([EMPTY]), increment empty_count and continue. - If cell is legitimate reserved placeholder ([RESERVED]), continue. - Otherwise, increment occupied_count. - Check Reserved Desk: If $(r, c)$ exists in reserved_coords, record violation in reserved_violations. - Check Duplicate Allocation: Search seen_students. If current roll number is already present, record tuple (roll, original_pos, current_pos) in duplicate_errors. Else, append roll and position to tracking lists. - Step 4 (Adjacency Inspection Loop): Iterate through non-empty, non-reserved cells: - Extract branch prefix (first 2 characters). - Compare with right neighbor $(r, c+1)$ if $c + 1 < C$. If right neighbor has matching branch prefix, record horizontal violation. - Compare with down neighbor $(r+1, c)$ if $r + 1 < R$. If down neighbor has matching branch prefix, record vertical violation. - Step 5 (Audit Summary): Sum all errors. If total_errors == 0, output [PASSED - AUDIT APPROVED]; otherwise, output [FAILED - REMEDIATION REQUIRED] with itemized findings. ---

    READ rows, cols, hall_grid, reserved_coords

    seen_students = []
    seen_positions = []
    duplicate_errors = []
    reserved_violations = []
    adjacency_violations = []

    FOR r FROM 0 TO rows - 1:
        FOR c FROM 0 TO cols - 1:
            val = hall_grid[r][c]
            IF val == "[EMPTY]" THEN
                empty_count = empty_count + 1
                CONTINUE
            END IF
            IF val == "[RESERVED]" THEN CONTINUE

            // Reserved violation check
            FOR EACH (rr, rc) IN reserved_coords:
                IF r == rr AND c == rc THEN
                    APPEND (r, c, val) TO reserved_violations
                END IF
            END FOR

            // Duplicate student check
            found = FALSE
            FOR k FROM 0 TO LENGTH(seen_students) - 1:
                IF seen_students[k] == val THEN
                    found = TRUE
                    orig_pos = seen_positions[k]
                    BREAK
                END IF
            END FOR

            IF found THEN
                APPEND (val, orig_pos, (r, c)) TO duplicate_errors
            ELSE
                APPEND val TO seen_students
                APPEND (r, c) TO seen_positions
            END IF
        END FOR
    END FOR

    // Adjacency check
    FOR r FROM 0 TO rows - 1:
        FOR c FROM 0 TO cols - 1:
            val = hall_grid[r][c]
            IF val is active student THEN
                IF c + 1 < cols AND hall_grid[r][c+1] has same branch THEN
                    APPEND horizontal violation
                END IF
                IF r + 1 < rows AND hall_grid[r+1][c] has same branch THEN
                    APPEND vertical violation
                END IF
            END IF
        END FOR
    END FOR

    total_errors = LENGTH(duplicate_errors) + LENGTH(reserved_violations) + LENGTH(adjacency_violations)
    PRINT audit findings and final verdict

When university admissions and departmental offices collect student registration profiles online, datasets suffer from data entry errors, malformatted fields, non-standard naming casing, invalid mobile numbers, out-of-bounds CGPAs, and duplicate registrations. The objective is to design and implement an automated data consistency checker that parses heterogeneous student records stored as tuples, verifies institutional integrity rules, sanitizes valid data into standardized formats, generates an itemized audit discrepancy log for flawed records, and calculates a holistic Database Health Index. ---

2. Objectives

- Unpack and process heterogeneous student profile tuples containing text, numerical strings, and codes. - Implement rule-based data validation without relying on forbidden libraries (re for regular expressions, pandas, or third-party schema validators). - Verify institutional Roll Number pattern rules (YYBBSS) and ensure cohort uniqueness without set structures. - Standardize human name formatting into proper Title Case while stripping illegal symbols or numerical digits. - Validate email syntax (single @ delimiter with a following valid domain dot) and mobile telephone conventions (10-digit format with valid initial service provider prefix 6-9). - Perform type casting and range validation for academic CGPA metrics ($0.00 \le CGPA \le 10.00$). - Strictly follow 1st-year B.Tech syllabus constraints: variables, conditionals, loops, string slicing/methods, lists, and tuples. ---

3. Assumptions

- Each incoming student profile is structured as a 7-element tuple: (roll_number, full_name, email, phone, cgpa_str, branch, date_of_birth). - Valid roll numbers are strictly 6 alphanumeric characters: 2 year digits, 2 branch letters, and 2 serial digits (e.g., 26CS01). - Valid academic branches belong to the approved institutional list: ['CSE', 'ECE', 'EEE', 'MECH', 'CIVIL', 'IT', 'CS']. - Phone numbers can be supplied with optional country codes (+91 or 91) or leading zero (0), but must resolve to exactly 10 digits beginning with 6, 7, 8, or 9. - Any record violating one or more rules is quarantined into the flagged log without polluting the sanitized database. ---

        LOOKUP room IN rooms

Case Study 88: Multi-Branch Retail Inventory Transfer

1. Problem Statement

Retail supply chains and collegiate cooperative bookshops operating across multiple regional branch campuses regularly experience localized inventory imbalances. While one branch may face a severe stockout deficit of textbooks or laboratory drawing kits, a neighboring branch may hold idle surplus inventory. Procuring fresh stock from external manufacturers takes lead time and incurs procurement costs, whereas rebalancing existing internal inventory between branches minimizes dead stock and fulfills customer demand quickly. The objective is to design a multi-branch inventory reconciliation engine that analyzes $M \times N$ 2D stock matrices, identifies surpluses and deficits, executes an automated greedy inter-branch stock transfer algorithm, and audits residual deficits requiring external vendor re-ordering. ---

2. Objectives

- Represent multi-location inventory using 2D nested lists (current_stock and target_stock of dimensions $M \times N$). - Compute a net variance matrix ($Variance = Current - Target$) to classify branch inventory into Surplus ($>0$), Deficit ($<0$), and Balanced ($=0$). - Design and implement an inter-branch transfer loop that matches donor branches to recipient branches product-by-product. - Track discrete transfer directives stored as tuples: (product, from_branch, to_branch, quantity, logistics_cost). - Compute aggregate logistics expenditures based on a fixed unit transit fee. - Reconcile post-transfer inventory levels and generate automated purchase orders for unresolved deficits. - Strictly adhere to 1st-year B.Tech syllabus limitations: loops, conditionals, 2D nested lists, lists, and tuples (no functions, no classes/OOP, no dictionaries, no NumPy). ---

3. Assumptions

- There are $M = 4$ branches: Campus-North, Campus-South, Campus-Central, Campus-East. - There are $N = 4$ stock items: Python Textbooks, Lab Notebooks, Scientific Calculators, and Engineering Drawing Kits. - Unit transportation handling cost is fixed at $\text{Rs. } 8.50$ per relocated item. - Intra-network transfers always take priority over external re-orders. - If total network stock for an item is less than aggregate branch targets, the residual unmet deficit is flagged for Central Vendor re-ordering. ---

4. Algorithm

- Step 1: Read lists of branch names and product names. - Step 2: Populate $M \times N$ 2D matrices for current_stock and target_stock. - Step 3: Compute $M \times N$ variance_matrix where $Variance[i][j] = current\_stock[i][j] - target\_stock[i][j]$. - Step 4: Initialize working_stock as a deep duplicate of current_stock and transfer_directives = []. - Step 5 (Product-by-Product Transfer Loop): For each product column $j \in [0, N-1]$: - While transfers are possible: - Search for first branch $i_{donor}$ where $working\_stock[i_{donor}][j] > target\_stock[i_{donor}][j]$. - Search for first branch $i_{rec}$ where $working\_stock[i_{rec}][j] < target\_stock[i_{rec}][j]$. - If both exist: - $available\_surplus = working\_stock[i_{donor}][j] - target\_stock[i_{donor}][j]$. - $needed\_deficit = target\_stock[i_{rec}][j] - working\_stock[i_{rec}][j]$. - $transfer\_qty = \min(available\_surplus, needed\_deficit)$. - $working\_stock[i_{donor}][j] -= transfer\_qty$. - $working\_stock[i_{rec}][j] += transfer\_qty$. - Append (product[j], branch[i_donor], branch[i_rec], transfer_qty, transfer_qty * 8.50) to transfer_directives. - Else: - Terminate while loop for this product. - Step 6 (Post-Transfer Audit): Traverse reconciled working_stock against target_stock. If $working\_stock[i][j] < target\_stock[i][j]$, append remaining deficit to external_procurement_needed. - Step 7: Display the pre-transfer variance grid, transfer manifest, post-transfer status matrix, and external purchase order requirements. ---

    READ branches (M items), products (N items)
    READ current_stock (M x N matrix), target_stock (M x N matrix)

    variance_matrix = []
    FOR i FROM 0 TO M - 1:
        row = []
        FOR j FROM 0 TO N - 1:
            APPEND (current_stock[i][j] - target_stock[i][j]) TO row
        END FOR
        APPEND row TO variance_matrix
    END FOR

    working_stock = COPY(current_stock)
    transfer_directives = []

    FOR j FROM 0 TO N - 1:
        CONTINUE_LOOP = TRUE
        WHILE CONTINUE_LOOP:
            donor = -1, rec = -1
            FOR i FROM 0 TO M - 1:
                diff = working_stock[i][j] - target_stock[i][j]
                IF diff > 0 AND donor == -1 THEN donor = i
                IF diff < 0 AND rec == -1 THEN rec = i
            END FOR

            IF donor != -1 AND rec != -1 THEN
                surplus = working_stock[donor][j] - target_stock[donor][j]
                deficit = target_stock[rec][j] - working_stock[rec][j]
                qty = MIN(surplus, deficit)

                working_stock[donor][j] = working_stock[donor][j] - qty
                working_stock[rec][j] = working_stock[rec][j] + qty
                fee = qty * 8.50
                APPEND (products[j], branches[donor], branches[rec], qty, fee) TO transfer_directives
            ELSE
                CONTINUE_LOOP = FALSE
            END IF
        END WHILE
    END FOR
